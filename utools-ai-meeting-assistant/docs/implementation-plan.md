# AI 会议助手实施计划

版本：V1.0  
更新时间：2026-08-27  
当前阶段：uTools 客户端优先  
后端阶段：客户端达到完成门槛后启动

## 1. 实施目标

当前集中开发：

```text
/Users/Zhuanz1/develop/src/tiehu-fitness/utools-ai-meeting-assistant
```

实施顺序：

1. 完成 uTools 插件的界面、状态、录音、桌面能力、Mock 数据、异常处理、测试和打包。
2. 固化客户端需要的 HTTP/WebSocket 契约。
3. uTools 客户端通过完成门槛后，再开发 `tiehu-fitness` 后端会议 API、ASR 和 LLM。
4. 最后执行真实前后端联调与发布验收。

当前不进入 Go 后端会议模块开发。客户端阶段只维护接口文档、Mock Gateway 和协议草案，避免后端实现反过来限制尚未验证的插件体验。

## 2. 进度口径

任务状态统一使用：

- `未开始`：没有可验证产物。
- `进行中`：已有部分实现，但未达到验收条件。
- `受阻`：依赖外部选择、权限、设备或服务。
- `已完成`：代码、测试、构建和相关文档达到该任务验收条件。

进度百分比是基于任务完成度的工程估算，不代表已经具备上线条件。只有“已完成”的任务可以按 100% 计入。

## 6. 客户端完成门槛

只有以下条件全部满足，才把主要开发重心转向后端：

- [ ] uTools 真实环境主流程和生命周期验证通过。
- [ ] Mock 模式完整覆盖首次进入、开始、转写、断线、停止、总结、历史、导出和删除。
- [ ] 麦克风长会议录制稳定，内存没有无界增长。
- [ ] macOS 系统音频方案已经验证并做出明确版本决策。
- [ ] WebSocket v1 协议包含 ACK、重连和恢复语义。
- [ ] HTTP 契约、错误 reason、分页和幂等要求已经冻结。
- [ ] 单元、组件、资源生命周期和协议测试通过。
- [ ] `npm run typecheck`、`npm run test`、`npm run build` 通过。
- [ ] 使用 `dist/plugin.json` 生成的 uTools 测试包可以安装运行。
- [ ] 未发现 token、音频、转写或纪要泄漏到日志和构建产物。

达到该门槛不表示产品已经上线，而是表示客户端已经稳定到可以让后端按固定契约实现。

## 9. 风险与决策点

| 风险 | 影响 | 处理方式 |
|---|---|---|
| macOS 系统音频采集方案不稳定 | 无法完整记录线上会议 | 提前做技术验证，不到发布前才确认 |
| 长会议音频积压 | 内存上涨或内容丢失 | 本地 spool、有界队列、ACK 和背压 |
| uTools 隐藏/退出生命周期处理错误 | 录音意外停止或无法停止 | 明确资源 owner，覆盖隐藏、分离、销毁测试 |
| WebSocket 契约过早固化 | 后端联调返工 | 先用 Fake Server 验证全部异常语义再冻结 |
| Mock 与真实后端响应漂移 | 联调时大量修改 | 共享 schema/contract test，外部 JSON 显式解析 |
| 隐私说明不准确 | 用户误解云端传输 | 区分“临时传输”和“保留原始录音” |
| 客户端先行导致后端约束遗漏 | 后续接口不适配 | 客户端阶段维护 API 草案，但延后实现而非停止设计 |
